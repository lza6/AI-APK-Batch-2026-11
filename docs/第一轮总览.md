## 关键结论

1. **这批 2024–2025 年的白标 AI App，AI 上游大面积停服**。wecall / nowtechai / sboomtools
   三条线里只有 wecall 的网站还活着，但它自己的 `/chat_stream` 也不吐数据了。
2. **AIChat 的加密层已完整解开**：`key="20190826"` `iv="00514321"`（DES/CBC/PKCS5），
   用它对上游 `/prompts/get_new` 的 15,628 字节密文解密，得到 11,717 字节 JSON、18 个 bot。
   这条链路已经跑在网关的 `/prompts/get_new?source=upstream` 里。
3. **能复刻的是协议，不是算力**。AIChat 的请求结构、SSE 帧格式、DES 响应加密调用链、
   bot 目录（`assets/bots.json`，含 20 个 bot 的 `token` 字段）都已还原；AMA 的
   NowAI / OpenAI / Poe / Gemini 四路客户端结构也已还原。
4. **加固强度梯度**：AIChat(PairIP) > GPTalk(IAP 加密 assets) > AnimeArt(native) >
   AMA(libconceal) > iMemo(无加固)。后两个只挡代码，不挡协议。
5. 真正卡住 GPTalk / Viddo / AnimeArt 的不是加固本身，而是**运行时才解密出端点**，
   静态拿不到路径；要继续就得在模拟器里跑起来抓包。

## 第二轮进展（同日晚）

**AIChat 的 DES key/iv 已解开**。默认 jadx 跳过的 `Parser.doGetKey` / `doGetIV` 用
`jadx --show-bad-code` 重跑后拿到完整实现：8 个 `"&#<n>"` 片段拼接后按 `&#` 切分，
逐段 `n ^ 65280` 转字符。

```
key = "20190826"    (k l m n l o k p)
iv  = "00514321"    (c c d e f g h e)
```

实测：用这对 key/iv 解上游 `/prompts/get_new?lang=en` 的 15,628 字节密文 → 11,717 字节
JSON、18 个 bot。这条链路已写进 `AIChat-WeCall/server/gateway.py` 的
`/prompts/get_new?source=upstream`，生产代码复验通过。

**模拟器动态抓包阻塞**。已经准备好 Android 33 `aosp_atd` x86_64 镜像（582MB）、
AVD `aosp33`、Frida 16.5.9（x86_64 + arm64 server）、`_tools/frida_capture.js`，
但 emulator 在这台机器上无法启动：`accel-check` 报告 WHPX 可用，实际
`qemu-system-x86_64-headless.exe` 启动即退，TCG（`-accel off`）、
无窗口/有窗口、清理 `multiinstance.lock` 均无效。这是虚拟化层的问题，不是分析链路的问题。

静态侧同步补到：`manage.magicutapp.com`（JSP 运营后台，`/appMagicCutApi/customizepage` 200）、
`/api/service_apis`、`/api/service_configs`（四个 host 上均 400/404，需要参数或签名）。

要继续动态抓包，需要以下任一条件：

1. 一台能跑 WHPX 的机器（或关闭 Hyper-V / WSL2 释放虚拟化层）；
2. 一台实体 Android 设备（`adb` 直连 + Frida server 按 CPU 架构）；
3. 若目标 App 有 Web 端，可退化为纯 HTTP 抓包。

Frida 脚本与抓包流程已经在 `_tools/frida_capture.js` 里，环境一通即可直接跑。

## 第三轮：纯静态深挖（同日晚）

模拟器走不通后改走纯静态，两条线都拿到了新东西。

**Viddo（Flutter）的字符串池继续挖出了完整端点**：

```
https://analytics.enjoymobiserver.com/vsAnalytics/1.0.1/clientDevice/activeDeviceReport.html?osType=1
https://analytics.enjoymobiserver.com/vsAnalytics/1.0.1/clientDevice/registerNewDevice.html?osType=1
https://analytics.enjoymobiserver.com/vsAnalytics/1.0.1/clientEvent/eventDataReport.html?osType=1
vsAnalytics/1.0.1/feedbackRecordClient/getReportTypeList.html?osType=1
vsAnalytics/1.0.1/feedbackRecordClient/reportFeedBackRecord.html?osType=1
vsAnalytics/1.0.1/qiniu/getUploadToken.html?osType=1
```

`qiniu/getUploadToken.html` 实测 **200**，回包里的
`"errorCode":"Failed in decoding inputData"` 直接点明了协议形状：参数叫 `inputData`，
是编码/加密后的载荷。内部包名也从 `libapp.so` 读出来了：`com.energysh.quickarte`，
源码路径 `package:quickart/aiservice/api/service_apis.dart`。

图片/内容侧确认 `camera.magicutapp.com/appCameraApi/` 是 API 宿主
（`getPic` 返回 302，其它 action 是 Spring Boot 404）。

**AnimeArt** 的 native 库职责查清了：`libZFutureLib.so` 只导出 6 个 JNI
（`decodeData` / `decodeToken1` / `generateBdStr` / `getcalsign` / `gqo` / `isJSValid`），
符号表里有 `aes_set_key`，整个库里没有任何 host/URL——它只做 AES + 签名，不发网络请求。
`assets/SignatureKiller/origin.apk` 里原版 4 个 dex 也查过，业务域名同样为 0。

**blutter 已经跑通**。Dart 3.4.3 / arm64，一共踩了 5 个环境坑（vcvars 未导入 →
`kernel32.lib`；ICU 只有 `lib64/`；中文目录被 MSVC 编成 GBK；链接选错 ICU 版本；
缺 `ntdll.lib`），全部解决后产出 `pp.txt`（61,178 行）与 `asm/`。

blutter 给出的关键结论：

```dart
static String getAnaUrl(String url) {
  if (url.startsWith("http")) return url;
  return "https://analytics.enjoymobiserver.com/" + url;
}
```

analytics 网关的 base 是 `https://analytics.enjoymobiserver.com/`，**5 条端点 POST JSON
全部 200**（`registerNewDevice` / `activeDeviceReport` / `eventDataReport` /
`getUploadToken` / `getReportTypeList`），实测压测 `eventDataReport` ×20 零失败
（p50 455ms / p95 1088ms）。请求体字段来自 `ServiceConfigs`：
`appId, appTime, appVersion, channelName, deviceUuid, isVip, lang, osVersion,
phoneModel, pkgName, uuid, version, versionName`。

AI 生成侧仍缺 action：`aiType`（`TextToVideo` / `aiTextToVideo3` / `aiTextToVideoExtend`）
是业务枚举不是 URL，`asm/quickart/` 下所有 `http` 常量都指向 analytics 网关或商店链接。

验证脚本：`Viddo-VideoShow/server/probe_analytics.py`。
